## 设计

### 已核对的问题与基线

- 当前 3 份题集共 52 条：33 条可答、19 条拒答。33 条标准证据均未绑定文档版本、页码或分块，仅凭标题和宽泛关键词判定。
- `evaluate_answer()` 目前只判断词语是否出现，不能区分肯定步骤与否定描述；只要至少一条引用相关，其他错误引用仍可能被忽略。
- `evaluate_retrieval()` 的 `recall_at_k` 当前是 0 / 1 的是否命中；M1 将在新报告中准确命名为 Hit@K，不声称已计算覆盖所有标准证据的 Recall@K。
- Chunk 从 0 编号，而 `RelevantSourceRule` 将 `chunk_indexes` 与必须大于 0 的数据库 ID 共用校验；M1 将允许分块 0，数据库 ID 与页码仍按各自实际语义校验。
- 既有表头修复尚未进入 main；固定回看 1 块会漏掉 v18 的 `1097/1098`，自身范围与邻接守卫也使用了不同声明判定。具体旧实测见末尾深入分析。

### 1. 核准题目和标准证据

- 旧 `*_v1.jsonl` 和历史结果保留。建立可追溯的 v2 题集，每个原 caseId 保持关联，记录修订原因、标注状态及标准证据。
- 逐项核对原题、所选型号、手册原文和适用范围。可答题的标准来源绑定版本及页码 / 分块，并保留必要的原文事实或动作依据；不能用当前模型生成答案反推标准。
- “拒绝访问”若只能找到其他型号说明，必须先核对完整的相关章节；没有充分依据时标记待复核，不能为了提高通过率直接改为拒答。
- 运行前核对 Java 下发的测试版本白名单与语料指纹。版本或分块映射变化时停止使用旧标注，不把环境中的同号 ID 当作同一文档。指纹按实际固定语料计算，不在设计里预填。
- 未核实样本单列数量与原因，不计入质量准确率；同时报告标注覆盖率。验收前原 52 条必须逐条有已核实结论，或明确的待复核清单与对验收的影响。

### 2. 统一连续型号范围

- 同一白名单文档版本内按 `chunk_index` 排序，统一使用 `section_model_codes()` 识别自身明确声明、独立型号表头和含目标型号的多型号列表；自身明确声明优先于前段继承。
- 对连续表格 / 同一段落，在没有新边界时继承前一段明确型号范围，覆盖多个无重复表头的续块，不简单增加固定回看常量。
- 新型号表头覆盖旧范围；可确认的新章节或共享声明结束旧范围。普通正文提及、耗材编号和故障码不作为型号边界。需要结合原文核对章节边界，不能只把任意 `heading` 变化当作共享声明。
- 不跨文档版本、缺失块或无法确认的章节边界盲目继承。扫描截断 / 失败或候选缺少前序上下文时，在原白名单内补查必要文本；仍无法恢复范围的候选按未知处理，不据此生成型号专属结论。已确认的共享说明不因前一型号表格被误删。
- 过滤统一作用于向量、词法和邻接候选，在融合、排序和生成之前完成。单块混合多组型号且无法区分适用行时保守处理，并列为 M2 的解析边界，不假定整块都适用。
- 缓存算法版本随实际修复更新，旧回答不继续命中；不删除业务数据，不改变现有持久化结构。

### 3. 修正评测口径

- 检索：对可答题报告 Hit@K、MRR、相关 / 无关证据数和错误型号证据；对拒答题单列是否仍返回资料。检索噪声与回答拒答分别计分。
- 回答：分别核对回答 / 拒答状态、引用身份与范围、必要事实 / 动作、明显相反或否定描述。关键故障有明确的事实规则与反例；无法自动判断语义的答案标为需人工复核，不宣称自动证明正确。
- 补充“错误版本 / 错误分块、只有菜单、关键词全部出现在否定句、部分正确引用夹杂明确错误型号引用”等评测器反例，保证它们不会仅凭关键词被计为正确。
- 不是每条非标准引用都等于错误：未标注但可能有效的同义证据进入复核；已确认其他型号或不支持结论的引用不能被一条正确引用抵消。
- 新离线报告记录题集版本 / 哈希、语料指纹、测试版本范围、算法版本、模型名、开发 / 保留分组、标注覆盖率与执行成功率。原始结果留在忽略目录，历史报告不回写。
- 网络、超时或模型错误计为执行失败，保留实际状态码 / 错误码，不猜测证书根因。质量统计展示分母与有效调用覆盖率，错误样本不能被静默删除以提高总通过率。
- 离线评测 JSON 会增加版本与复核字段，并把错误命名的指标改为 Hit@K；旧报告继续可读，但不直接混合比较新旧通过率。线上 RAG 接口不变。

### 4. 开发题与保留题

- 已查看过的 52 条全部作为开发回归，不把随机切出的一部分追认为从未见过的盲测。
- 算法和规则冻结后，新增 12 条保留题，3 个型号各 4 条，包含可答和拒答。按故障 / 任务组与开发题去重，避免同一道题的改写横跨两组。
- 保留题只用于冻结版本的首次评估，不根据其结果继续调参后仍称盲测。如用失败题调参，转入开发回归并建立下一版保留题；同一开发者构建的保留题不宣称独立盲测。
- 保留题的来源、标准证据和首次执行版本均可核对；必要时由用户复核，不用未经核实的自动生成标准答案。

网络诊断：

- 不带密钥访问 DeepSeek 认证端点，HTTPX 曾抛出 `SSLCertVerificationError`；三组对照中默认 HTTPX 为 2 次 HTTP 响应、1 次校验失败，系统证书上下文为 3 次 HTTP 响应。失败码为 `19`，原因为 `self-signed certificate in certificate chain`。所有对照都开启证书及主机名校验。
- 无密钥探测收到 HTTP 401 说明 TLS 已完成并收到认证响应，该 401 与先前 LangSmith 追踪上报的 401 属于不同请求。SiliconFlow 的两种客户端探测均收到 HTTP 响应。
- 当前已复现的是 HTTPX 路径上的间歇性证书信任问题。证书链来源仍未核实，不能直接归因 DeepSeek 服务故障；此前 9 条只记录 `CHAT_MODEL_UNAVAILABLE`，不能回填为全部证书失败。
