# 阶段 04：文档结构保留与分块预览（M2-1）

## 目标与用户看到的效果

M1 已验收并推送。用户要求“继续”，本轮进入 M2 设计。总体路线 M2 的目标是保留文档结构与来源；拆为先做结构与预览，再设计索引迁移、发布与回退。本阶段只交付第一部分，不能据此宣称整个 M2 完成。

文档管理员在现有文档版本列表打开“结构与分块预览”，查看原文块、章节路径、表格单元格、型号组和来源锚点，对比现有规则与结构化规则的分块结果。预览不触发重新解析、Embedding、索引或模型回答，用户能判断一行故障及其处理步骤是否被正确保留。

## 范围与不做

- 基于已验收 M1 交付 `fe5c6f5da0a537deabf18a1a564e587cfd725bd1`，在独立工作区分支 `codex/m2-document-structure` 设计和开发；主目录、M1 分支及旧工作区保留。

- 本阶段不把新的结构化分块接入正式索引或问答；现有 `chunk_document()`、检索排序、缓存算法版本及原 52 + 12 条题集保持原口径。预览里使用“现有规则预览 / 结构化规则预览”，不声称等同于历史索引中的实际分块。
- 不改 Milvus Schema，不创建或重建向量集合，不混用新旧索引，不做 BM25、Reranker、故障同义改写、PDF 高亮、人工发布审批或版本回退界面。这些分别留给 M2 后续设计、M3 / M5。
- 不新增依赖、锁文件、数据库表 / 列、SQL 迁移、菜单权限种子或全局配置。使用已有 Python 标准库、Java / Vue 组件与测试依赖；解析结构保存在已有解析 JSON 中，仍由 Java 的 `parsedObjectKey` 引用。
- 用户已确认本设计并授权开发。开发自检包含本地确定性测试；独立测试、验收和提交 / 推送另按用户安排。

## 设计

### 已核对的现状与拆分依据

- `DocumentBlock` 目前只有 `sequence / pageNumber / blockType / text`；MinerU 的标题层级被简化为 heading，HTML 表格被压为制表符文字，拆分 PDF 合并时也只复制这四个字段。DOCX 表格同样没有保留单元格跨度。
- 现有分块按单个标题与页码归组，再按字符切开；`blockStart / blockEnd` 只表示整个组，不能准确说明候选文本来自哪一行或哪段字符。
- Java 将反序列化后的解析 DTO 存成 JSON，新增 Python 字段若不同时进入 Java DTO，会在保存和后续索引请求中丢失。当前解析结果固定写到 `parsed/parse-result.json`，重解析会使用相同对象键。
- 当前 `replace_version()` 先按文档版本删除向量，再分批 upsert；Java 上传新版本会立即更新 `currentVersionId`，同文件哈希的重复版本会被拒绝。因此不能把“换分块后原地重建”当作可回退升级，也不能假定重新上传相同文件即可产生处理版本。
- 本阶段先提供可检查、可追溯的候选结构；处理代次、发布切换、索引迁移与回退在下一阶段另写设计，不能以预览结果直接覆盖当前知识。

### 1. 保留抽取结构，兼容原有文字

- 解析结果新增 `schemaVersion=2` 与本地归一化规则版本 `normalizationVersion`；不将该规则版本冒称为 MinerU 服务端版本。缺少字段的旧 JSON 作为 v1 读取。
- `DocumentBlock` 保持原四个字段及其含义，附加可空的 `headingLevel / sourceItemIndex / sourcePartIndex / table`。表格保留行、单元格顺序、单元格文字、`rowSpan / columnSpan`，以及表题和脚注的来源关系。原 `text` 继续用既有文字生成规则，不因附加结构改变旧索引输入。
- MinerU 优先保留实际返回的标题级别和 HTML 单元格关系；PDF 分片合并同步调整原文页码并保留附加结构。DOCX 使用文件中可确认的标题 / 表格信息；缺少的页码、层级或跨度标为未知，不根据文字长度、空格或行号编造。
- 本地 PDF 仍可能只有整页文字；TXT 没有可靠版式。界面显示实际具备的结构，不把纯文字加载器写成已经恢复表格布局。
- 表格解析沿用标准库 HTML 解析方式；表头只采用明确单元格类型或经验证的结构规则，不能无条件把第一行当列名。合并单元格保留原位置与跨度，未知结构加提示，不复制出虚假的不同原文单元格。
- Java DTO、解析保存、读取和索引请求转发同时保留附加字段；旧 JSON 的反序列化和原有统计继续可用，字符数仍按旧 `text` 统计，不能重复计入单元格。

### 2. 生成可追溯的候选分块

- 新增独立的结构化候选分块器，仅供预览调用；正式 `DocumentIndexingService` 继续调用原分块器。
- 按已知标题层级维护章节路径。无层级的标题只作可确认的边界，不猜测父子关系。型号范围沿用 M1 的确定性声明识别，记录所依据的源块 / 型号组；明确共享、受限与未知分开显示。
- 表格按行组织“表题 + 已知表头 + 当前行”，保留列对应关系。型号组变化时切分，不能把一个包含多组型号的块无条件视为所有组适用。
- 跨页续表只有在章节、列布局、型号范围及连续来源均能确认时关联；无法确认则保持分离并提示。复用的表头 / 型号声明标明其原始来源，不能伪装成当前页新抽取的内容。
- 过长段落 / 单元格按实际可用字符预算切分，保留同一行的连续片段关系；表头开销计入长度，不通过串入相邻行凑满长度。相邻块重叠只在相同章节和范围内进行。
- 每个候选保留来源清单：源块序号、原文页码、表格行 / 单元格位置或文字字符区间。页码是原 PDF 页，不是截取后的小文件页；DOCX / TXT 无可靠页码时为空。
- 候选身份绑定 `parseId + 分块规则版本 + 有效参数 + 来源 + 文字摘要`。预览序号与 M1 的 `chunkIndex` 不互相冒用，旧题集标准来源和历史成绩不改写。

### 3. 解析结果身份与兼容读取

- 新解析 JSON 使用含内容摘要的对象键，完整保存后再更新现有 `parsedObjectKey`；不覆写已经被历史版本引用的 JSON。旧固定路径仍可读取，本阶段不自动批量重解析。
- Java 从数据库版本获取对象键并读取文件，校验原文件哈希及解析统计；按所保存的解析 JSON 字节计算 `parseId`，作为预览所使用的确定结果身份，避免 Java / Python 分别序列化后得出不同摘要。
- 新接口不接受浏览器提供的文件路径、对象键、解析正文或授权范围。AI 仅接收 Java 已核对的解析内容及不透明 `parseId`，返回同一身份；Java 和前端不能把迟到的其他版本结果显示为当前预览。
- 版本删除后立即拒绝预览；派生解析文件清理使用服务端确定的该版本存储前缀，覆盖该版本的新旧派生 JSON，保留一键删除能力。不得接受客户端传入清理路径。
- 这一步只保证解析来源和预览一致，不声称已经解决索引切换的事务性。既有任务、业务版本、索引状态和会话状态保持各自职责。

### 4. Java → FastAPI 只读预览接口

- 新增 Java `GET /officecare/document/versions/{documentVersionId}/preview`，参数为 `view=blocks|legacy|structured` 与分页；服务端固定可用规则，限制页大小，先完成上下文解析再分页，翻页不能改变范围判断。
- 预览会返回原文内容，权限同时要求现有 `officecare:document:query` 与 `officecare:document:download`，并沿用现有单企业文档 / 知识库归属检查；不能仅凭版本 ID 绕过 Java。无需新增权限菜单或业务租户概念。
- 新增 FastAPI 内部 `POST /api/v1/internal/documents/preview`，继续使用已有内部 Token；输入为 Java 验证过的版本、原文件哈希、`parseId`、解析块和预览参数。该路径只调用纯解析 / 分块函数，不实例化 Embedding、Milvus 或回答服务，不创建后台任务。
- 输出包含文档版本、`parseId`、规则 / 有效参数、候选总数、来源锚点、范围状态与结构提示。未解析、文件哈希不符、不支持的结果版本等返回明确错误，不自动触发解析或降级成成功。
- 旧 v1 结果允许原文和现有规则预览；无法确认的结构显示缺失说明，不把从扁平文字猜测出的合并关系标为已验证。

### 5. 文档管理员的预览界面

- 在现有文档版本列表增加“结构与分块预览”，对应三个视图：原文块、现有规则分块、结构化规则分块。
- 展示原文页码 / 源块、章节路径、按行展开的表格、型号范围和缺失结构提示；候选卡片明确为预览，不能据此写入向量库或改变当前问答内容。
- 使用文本插值和受控表格组件呈现单元格，不能把来自解析器的原始 HTML 直接送入 `v-html`。切换文档 / 版本 / 视图时取消或丢弃旧响应，保留分页与加载 / 失败状态。
- 旧结果、无可靠页码、混合型号和无法确认的续表均有可见说明；不添加无效的 PDF 高亮按钮、发布按钮或与本阶段无关的运行看板。

### 数据、外部服务与迁移边界

- 开发自检使用合成 PDF / DOCX / MinerU 返回夹具及现有测试用例；有真实原始归档时，优先在本地重放。M1 的扁平分块快照不能充当“已恢复原始单元格”的证据。
- 当前尚未核实可复用的真实 MinerU 原始结构归档。本阶段设计确认不等于授权将手册全文重新上传 MinerU，也不等于授权批量 Embedding；如确需真实解析，先列明具体测试文件、供应商及外发范围，另行获得授权。
- 本阶段不调用 SiliconFlow / DeepSeek 真实评测，不重跑 M1 保留题，不承诺检索通过率提升。旧索引的保护依靠不切换正式分块路径，而不是只在 Prompt 中约定。
- 不新增依赖、数据库迁移或 Milvus 字段；唯一存储变化是新解析派生文件的对象键与 JSON 附加字段。现有解析后自动索引流程保持原规则，不能在本阶段偷偷改成新的发布流程。

## 内部步骤

3. 实现结构化候选分块和内部只读预览，保留现有索引调用路径；按固定夹具核对表格行、型号范围与来源。

6. 将实际结果、未测项、commit 与源码入口补在本文末尾，再按用户安排验收。未验收前不开始 M2 后续索引升级，也不提交或推送。

## 验证方式

- 按用户新增的“最小够用”原则，只补关键业务和实际风险的测试，不设最低用例数，不追求字段组合穷举；不为测试新增依赖或给生产代码添加测试专用分支。

| 类别 | 主要场景 |
|---|---|
| 结构解析 | 标题层级、HTML / DOCX 合并单元格、PDF 分片原页码、脚注关系、未知布局、原文字兼容 |
| 候选分块 | 行列对应、型号组切换、共享 / 未知范围、可信续表、拒绝错误续接、超长行来源与预算 |
| 服务契约 | v1 兼容、版本 / 哈希不符、权限与删除后失效、分页保持来源及范围一致 |
| 界面与副作用 | 三视图正确展示、纯文字安全渲染、快速切换不串版本、预览没有解析 / 索引 / 模型调用 |

- Python 按现有 pytest 配置自检，Java 按现有 Maven 测试与构建命令，前端按现有 `npm test` 和 `npm run build:prod`；结果只写实际执行的命令与输出，不预填通过。
- 必须证明同一固定解析输入的旧 `text`、原分块和索引请求旧字段保持兼容；结构化预览确定、来源能还原对应行或字符，错误范围不能被共享声明抵消。
- 必须证明预览不写 MySQL 业务状态、不排队解析 / 索引、不访问 Milvus 或外部模型；需要写入的生命周期测试仅使用 `*_test` 资源，不连接开发库。
- 验收目标是可检查的结构与来源，不是回答质量达标、正式索引迁移完成或整个 M2 完成。真实 MinerU / 复杂扫描版式如未运行，按未验证登记，不用合成夹具冒充。
